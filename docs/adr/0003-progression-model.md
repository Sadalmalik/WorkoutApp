# 0003. Прогрессия как подключаемая стратегия, индексируемая выполнениями и выводимая из истории

## Контекст

Рост нагрузки задаётся по-разному: точная сетка «неделя → сеты/повторы/вес», авто-рост на `+N`, адаптивный сдвиг «не выполнил — не поднимаем», и наверняка более сложные зависимости позже. При этом расписание может быть не календарным (см. [ADR 0001](0001-scheduling-model.md)), поэтому привязка прогрессии к календарной «неделе» невозможна. Плюс правило «met/не met» пользователь ещё не считает окончательным.

## Решение

Прогрессия — подключаемая стратегия, живущая на записи упражнения внутри блока (не в каталоге упражнений: одно упражнение в разных программах может расти по-разному).

- **Единица шага — число выполнений слота**, а не календарная неделя. В недельной программе (упражнение раз в неделю) это совпадает с «неделей».
- **Модель сетки — три слоя**: базовые цели (`{вес, повторы}` по сетам) → явные переопределения конкретных шагов → правило продолжения за пределами явных шагов (в Фазе 2 — линейный `+N` по весу/повторам; шаг веса берётся от снаряда упражнения).
- **Текущий шаг выводится из истории результатов**, а не хранится изменяемым счётчиком: сдвиг на следующий шаг происходит, только если предыдущий выполнен целиком (все сеты достигли цели при весе ≥ целевого), иначе шаг повторяется. Даётся ручной override.
- Правило «выполнено» (все сеты / верхний сет / объём) — точка расширения; дефолт — все сеты.

## Рассмотренные альтернативы

- **Календарная индексация («неделя»)** — разъезжается с некалендарным расписанием и с реальной частотой тренировок.
- **Хранимый счётчик шага** — рассинхронивается при правке/удалении истории; вывод из истории самокорректируется.
- **Единственный зашитый алгоритм роста** — не покрывает и точную сетку, и авто-рост, и будущие зависимости.

## Последствия

- Правка/удаление прошлого результата автоматически пересчитывает текущий шаг (история — источник истины).
- Новый алгоритм роста или новое правило «выполнено» = новая реализация стратегии, без изменения модели данных.
- Реализуется в Фазе 2; в Фазе 1 цели статические (как v1, редактируются вручную).
